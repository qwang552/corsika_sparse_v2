# corsika_sparse_v2

> **Status: work in progress.** The model is still being improved, and the generated
> showers do not yet fully match CORSIKA 8. Use them for testing and visualization only,
> not for physics analysis.

A generative model for the Cherenkov light of CORSIKA 8 in-ice showers. It
produces the full photon distribution (`NPhotons` per position) on a sparse
192³ voxel grid, without running CORSIKA.

Commands, and the paths to change on your own machine, are in `RUN_ORDER.md`.
This file explains what the model is, why it is built this way, and how it is
evaluated.

## 1. Problem and data

**Input data.** CORSIKA 8 in-ice showers, 1 TeV only, 16,000 simulated showers
(ids 0 to 15999); the showers that pass the cuts below are in the cache
(`metadata.json` lists them). Each event is a list of Cherenkov records (`NPhotons`, `time`, `posX/Y/Z`, direction).

**Region and resolution.** To make the first version learnable, the data are
cut to a 4 m cube at the front of the shower (x, y in [-2, 2] m, z in
[46, 50] m) and to records with time < 12 ns. The cube is divided into 192³
voxels of 2.08 cm. At this resolution individual track segments are visible,
while the number of active voxels per event stays in the tens of thousands.

**Voxel cache** (`sparseshower/data.py`). For every event, only non-empty
voxels are stored. Each stored voxel has:

- `ijk`: its index;
- `q`: the sum of `NPhotons`;
- `off`: the photon-weighted position inside the voxel;
- `t` and `m`: mean time and direction (stored, not modelled yet).

The events are split 80 / 10 / 10 into train / val / test. See `RUN_ORDER.md`,
section 3.

**Task.** Learn p(event), where an event is the set of active voxels together
with `q` and `off` of each voxel. Generation is unconditional, because all
events have the same energy and no angle information is available yet.

## 2. Why this design

The data are extremely sparse. Across 300 events at 384³, only 0.21% of the
voxels are non-empty. Most of the light sits on long, thin tracks, and a
halo of weaker light surrounds them. This has three consequences.

- **A dense 192³ grid is too large.** A dense network at 7 million voxels per
  event does not fit an 8 GB GPU. A point cloud of all photons, about 10⁸ per
  event, is far too large as well.
- **Calorimeter generators do not transfer directly.** Models such as
  CaloFlow and CaloClouds were tried first and worked poorly here. They are
  built for compact showers in a fixed detector geometry, not for long tracks
  in an open volume.
- **One model for everything is hard to debug.** When a single model fails,
  it is hard to tell which part of the problem it failed on.

The design therefore splits the problem coarse to fine. Each stage can be
trained and tested separately:

1. a small dense summary of the event (a 48³ field) carries the global shape;
2. a sparse structure model decides which fine voxels are active;
3. a sparse attribute model fills in the photons of each active voxel.

An earlier version (v1) conditioned the coarse field on a (z, r) summary
computed from the true event. That summary comes from the truth, so v1 cannot
generate a new event from scratch. In v2 the coarse field is generated by a
latent diffusion model instead.

The building blocks are standard: VAE-style autoencoder, DiT, EDM diffusion,
sparse attention. The combination is specific to this data. It has not been
benchmarked against every alternative.

## 3. The model

```
noise ──LatentDiT──> latent z (8 x 12³) ──FieldAE decoder──> 48³ field F = (p_occ, ch0, ch1)
      ──struct: 48³ -> 96³ -> 192³──> active 192³ voxels
      ──attr──> logQ and sub-voxel offset of every voxel
      ──T2 (optional)──> photons rescaled per 48³ cell to match F
```

### 3.1 The 48³ field (`fields.py`)

Each 48³ cell covers 4³ = 64 fine voxels (8.3 cm). Two channels:

- `ch0 = log(1 + n) / log(1 + 64)`: how many of the 64 fine voxels are active;
- `ch1`: standardized log photon sum of the cell (0 in empty cells).

This field is small enough for dense 3D convolutions, and it still shows
where the tracks are.

### 3.2 FieldAE, model 1 (`field_ae.py`)

A 3D convolutional autoencoder that compresses the 48³ field into a
latent of 8 x 12³ (2 x 48³ = 221,184 numbers -> 13,824, a factor of 16).

- **Encoder.** ResBlocks at 48³ -> 24³ -> 12³, with self-attention at 12³.
  It outputs a mean and a variance, as in a VAE with a very small KL weight
  (1e-6).
- **Decoder.** The mirror of the encoder, with three output heads:
  - an occupancy logit per cell, giving `p_occ`;
  - `ch0` and `ch1`.
- **Loss.**
  - Occupancy: weighted BCE. Occupied cells get a higher weight because they
    are only about 5% of the grid, and bright cells higher still.
  - Channels: MSE of `ch0` and `ch1`, on occupied cells only.
  - Profiles: L1 of the longitudinal and radial photon profiles, plus the
    log total photon count.
  - A small KL term.
- **Occupancy threshold.** A cell counts as occupied when `p_occ` is above a
  threshold. The weighted BCE pushes `p_occ` up, so 0.5 marks too many cells.
  A scan over thresholds (`ae_eval.sub` + `notebooks/ae_check.ipynb`) chose
  0.85 (`configs/v2_cal85.yaml`). At 0.85 no event loses more than 0.5% of
  its photons, and the extra cells carry about 2% of the photons.

### 3.3 LatentDiT, model 2 (`dit.py`)

A diffusion transformer on the standardized latent.

- **Tokens.** The 12³ latent is cut into 2³ patches, which gives 216 tokens.
- **Network.** 12 blocks, width 384, fixed 3D sin-cos position embedding.
- **Conditioning.** The noise level enters through adaLN-Zero. It is the
  only conditioning.
- **Training.** EDM (Karras et al. 2022): the network learns to denoise
  latents at random noise levels.
- **Sampling.** A Heun ODE solver from high noise down to zero.
- **SDEdit.** Start from a real test latent with noise σ_s added, instead of
  pure noise. Small σ_s stays close to that event; large σ_s approaches free
  generation. This gives paired comparisons for the DiT (section 4).

### 3.4 struct, model 3 (`structure.py`, `struct_data.py`)

Grows the active voxel set from 48³ to 96³ to 192³. Each active parent voxel
has 8 children on the next grid.

- **Output.** struct predicts which of the 256 possible child configurations
  the parent has. A joint 256-way choice keeps the 8 children consistent with
  each other; 8 independent yes/no outputs would not.
- **Backbone** (`nn_blocks.py`, `SparseNet`). It works on the list of active
  voxels only. Each block has three parts:
  - message passing between grid neighbours;
  - attention inside windows along a Z-order curve;
  - an MLP.

  A pooled global attention branch runs every two blocks. Positions enter as
  Fourier features.
- **Inputs per parent:**
  - the decoded field at its 48³ cell;
  - the local shape of the neighbourhood (a direction tensor, which shows
    whether the voxel lies on a straight track);
  - the children already chosen for its 26 neighbours;
  - a global vector g, encoded from the whole field.
- **8-colour sequential sampling.** Parents are coloured by the parity of
  (i, j, k). Parents of one colour never touch, not even diagonally. Colours
  are sampled one after another, so each parent sees the final children of
  its neighbours from earlier colours. This lets tracks continue from one
  parent into the next. Training draws a random colour step and uses truth
  for the earlier colours.
- **Augmentation.**
  - Parent sets are corrupted: real parents dropped, empty ones added.
  - Track cut: short pieces of known track are erased, so the model learns
    to continue a track across a gap.

### 3.5 attr, model 4 (`attr.py`)

Given the final 192³ voxels, attr generates 4 numbers per voxel: log photon
count and the 3D offset inside the voxel.

- **Method.** A sparse EDM diffusion model on the fixed voxel set, with the
  same `SparseNet` backbone.
- **Conditioning.**
  - Per voxel: the decoded field of its 48³ cell.
  - Global: its own field encoder.
- **Structure dropout.** During training a few percent of the voxels are
  removed. This makes attr robust to structure errors from struct.
- **T2 (sampling option, on by default).** After attr, the photons of each
  48³ cell are rescaled so that the cell's total matches the decoded field.
  This fixes the total photon count per region.

### 3.6 Training on reconstructed fields

In the sa_recon, sdedit and full chains, struct and attr see an AE-decoded
field, never the true one (sa_truth, a test chain, is the exception). They are
trained in the same way:

- the input field is the AE reconstruction of the training event (sometimes
  drawn from the AE posterior);
- the first struct level usually (`struct.recon_parent_p` = 0.75) starts from
  the decoded occupied cells, otherwise from a corrupted truth parent set;
- the targets are always the true voxels.

As a result, the models learn to correct small AE errors instead of
assuming a perfect field.

## 4. Sampling chains: separating the error sources

A generated event passes through four models, and each can add error. The
chains start at different points, so each model's error can be measured on
its own:

| chain | starts from | tests | paired with a test event |
|---|---|---|---|
| `sa_truth` | the true 48³ field | struct + attr only | yes |
| `sa_recon` | the test event's latent, decoded by the AE | + AE error | yes |
| `sdedit` σ_s | the test latent with noise σ_s, denoised by the DiT | + DiT error, growing with σ_s | yes, weaker as σ_s grows |
| `full` | pure noise | the whole generator | no (distribution level only) |

Reading the chains in this order works like a ladder. `summary.json` and
`passfail.md` call each evaluated sample set (one chain run, plus R0 and V1) a rung.

- `sa_truth` vs truth shows what struct and attr get wrong;
- `sa_recon` minus `sa_truth` is the AE's contribution;
- the `sdedit` sweep from small to large σ_s shows how the DiT drifts;
- `full` is the final result.

## 5. Evaluation (`evaluate.py`)

Every metric is first computed per event, then aggregated. The test split
is the truth.

### 5.1 Per-event statistics

For each event (true or generated):

- **Size:** active voxels, total photons, the photon share of the brightest 5%
  of voxels.
- **Profiles:** longitudinal (32 z-slabs) and radial (16 rings) photon profiles.
- **Texture:**
  - `straight_frac`: fraction of voxels whose neighbourhood is almost a
    straight line (PCA linearity > 0.95);
  - nearest-neighbour distance between voxels;
  - box-counting dimensions at 4 scales;
  - distributions of per-voxel logQ, nearest-neighbour distance and linearity
    (512 quantiles each).
- **Halo connectivity.** The halo is the voxels more than 0.5 m from the
  axis, with components connected through all 26 neighbours. Reported:
  - the number of components;
  - the photon share carried by components of 20 or more voxels
    (`halo_big_frac`);
  - the number of components longer than 0.6 m.

### 5.2 Baseline R0: truth against truth

Metrics need a scale: how different are two sets of *real* events? The test
events are split into halves A and B. The same statistic is computed for B
against A. This is R0, the level of difference that is only statistical noise.

### 5.3 Paired metrics (sa_truth, sa_recon, sdedit)

Each generated sample belongs to one test event. For every sample:

- relative errors of active voxels and total photons;
- L1 distance of the longitudinal and radial profiles;
- differences in `straight_frac` and halo numbers;
- W1 (1-D Wasserstein-1 distance) of the per-voxel distributions.

These are averaged over events with a bootstrap 95% confidence interval.

**own / other.** The longitudinal-profile L1 distance to the sample's own truth event,
divided by its distance to other test events. It is near 0 when the sample
still resembles its own event. It approaches 1 when the sample could be any
event, which is what SDEdit should show as σ_s grows.

### 5.4 Distribution metrics (every chain, including full)

- **W1 / R0.** For each event statistic: W1(generated, truth A) divided by
  W1(truth B, truth A), with B subsampled to the generated sample size.
  1 means as close as another set of real events; the working target is ≤ 2.
  The ratio depends on the size of the truth reference, so compare runs
  evaluated against the same test set.
- **C2ST.** A classifier two-sample test. A logistic regression tries to tell
  generated events from true ones, using standardized event features and
  their squares, with k-fold cross-validation. AUC 0.5 means they cannot be
  told apart and 1.0 means they are perfectly separable. The target is ≤ 0.65.
- **Fréchet distance** on standardized features. Currently unreliable: one
  profile bin has zero variance in the truth, which inflates the value.
- **Memorization** (full chain). The distance from each generated latent to
  its nearest training latent, divided by the same distance for validation
  latents. A ratio near 1 means no copying of training events; ≪ 1 would
  mean memorization.

### 5.5 AE acceptance (`ae_eval.sub`)

Decoded field vs true field on validation events, with no struct or attr
involved:

- the fraction of photons lost in cells the AE misses;
- the error in the number of occupied cells, and extra cells;
- profile L1 and total photon error.

### 5.6 Output

`<paths.output>/<case>/eval/<name>/` contains:

- `summary.json`: all numbers;
- `per_event.jsonl`: per-event paired errors;
- `passfail.md`: every metric against its threshold (thresholds in
  `configs/v2.yaml`; these are working targets, not physics requirements);
- `summary.png`.

`notebooks/report.ipynb` recomputes the metrics itself (no evaluate run
needed; 256 truth events by default, so its W1/R0 values differ from those of
evaluate) and writes numbered figures to `<case>/samples/report/`. It adds
voxel overlap (IoU) per grid level, timing, the SDEdit curve and 3D views.

## 6. Results so far (case v2a, 1 TeV)

These numbers come from the cluster run with the final checkpoints. The
truth reference is all 1,378 test events; the paired chains use 128 test
events.

- **Large-scale shape is reproduced by the paired chains.**
  - W1/R0 of size, total photons and profiles is 0.8 to 1.3.
  - Mean photon error per event: 0.9% (sa_truth) and 1.7% (sa_recon).
  - Longitudinal profile L1: 0.006 and 0.016.
- **Fine texture is not reproduced, even in sa_truth.** The problem therefore
  starts in struct / attr, before any AE or DiT error.
  - Generated events have fewer straight segments: `straight_frac` W1/R0 is
    about 14.
  - Their halo is more fragmented: `halo_big_frac` W1/R0 is about 25.
  - C2ST AUC is 1.0.
- **SDEdit sweep (σ_s = 0, i.e. sa_recon, to 5).**
  - Longitudinal L1 rises from 0.016 to 0.13.
  - Photon error rises from 1.7% to 20%.
  - own / other rises from 0.08 to 0.64.
  - Texture gets worse along the way: `straight_frac` W1/R0 goes from 14 to
    24, and `halo_big_frac` from 25 to 50.
- **Full chain.**
  - W1/R0 is about 5 for active voxels and for total photons.
  - Generated events are on average 12 to 14% smaller than real ones.
  - Memorization ratio is 0.98, so training events are not copied.
- **T2 is needed.** Without it, total photons are off by about 3% and the
  profile L1 is 5 times larger.

## 7. Next steps

1. Improve each of the four models separately. struct / attr texture comes
   first (straight tracks, halo connectivity), then the AE and the DiT.
2. Train on the full dataset with energy and angle as conditions.
3. Model the time evolution (`t` is already stored in the cache).

Known issues:

- the Fréchet distance needs zero-variance features removed (section 5.4).

| path | content |
|---|---|
| `sparseshower/` | the package; entry point `python -m sparseshower.cli <command>` |
| `configs/` | `data.yaml` (paths, data, shared settings), `v2.yaml` (models, thresholds), `v2_cal85.yaml` (threshold 0.85), `preprocess_192.yaml` (cache), `smoke.yaml` (self-test) |

| `trained_model/` | the trained model packed for `python -m sparseshower.generate` |

Quick start on any machine (full command list in `RUN_ORDER.md`):

```bash
pip install -r requirements.txt
python -m sparseshower.generate --n 10    # 10 new showers from trained_model/ into showers/
python -m pytest tests -q
python -m sparseshower.cli selftest      # whole chain on synthetic data; ends with "SELFTEST PASS"
```
